# v0.8.3: paid-response recovery and runnable archive examples

This patch fixes two defects reproduced against the public v0.8.2 distribution.

A paid response could fail while reading its body, decoding JSON, validating its
product schema or checking its receipt, then expose an ordinary error without
warning the caller against buying it again. JSON and screenshot processing now
preserves established OmniApiError/OmniContractError types and codes while adding
immutable requiresReconciliation:true, retryable:false and paymentOutcome:
"unconfirmed" metadata. Generic public request() calls are covered even when
there is no product contract or surviving receipt. Explicit free health requests
keep their existing error behavior. These flags are conservative recovery
instructions; they do not prove that a charge settled. The client never silently
replays the request or releases a payment authorization hold because parsing failed.

Packaged example scripts previously imported the development-only tsx loader.
The archive now contains compiled JavaScript examples using public SDK exports,
so an SDK-only consumer can run them on Node >=22.12 without installing a compiler
or loader. Free research and guarded preview commands explicitly override paid
or execution environment switches. The deterministic lifecycle runner is clearly
labelled mock-tested and makes no venue requests, signatures or orders.

## Install

Once the immutable tagged archive is published:

```sh
npm install https://github.com/InTheta/omni-universe-sdks/releases/download/v0.8.3/omni-terminal-sdk-0.8.3.tgz
```

See the [installed quickstarts](../installed-quickstarts.md) for exact archive paths, free commands and the
separate source installation required for the local stdio MCP trading adapter.
The adapter is not the public read-only seller MCP endpoint. Paid x402 calls,
application login, trading-agent permission and builder-fee approval remain
separate authorisations. Existing v0.8.1/v0.8.2 tags and assets are unchanged;
this does not claim npm registry publication.

## Verification boundary

Public-client injected-fetch fixtures exercise malformed JSON, interrupted bodies,
wrong products, missing/invalid receipts, HTTP errors, generic requests, screenshot
validation and redaction. These are deterministic fixtures with zero signing,
spending or network calls. Package verification installs only the SDK tarball,
compiles strict public TypeScript contracts and runs the compiled recovery example
and missing-scope guard without consumer development dependencies.

Live free quickstarts are reported separately from those fixtures. Funded SDK/MCP
execution, credit for a new builder-attributed order, signed payment expiry/replay
and a newly authorised paid Snapshot retry remain separate verification gaps.
