# v0.8.2: installable TypeScript declaration dependencies

This patch fixes a clean-consumer packaging defect in the immutable v0.8.1
GitHub archive. Its JavaScript imports worked, but a strict TypeScript project
installing only the SDK could not compile the published declarations: the
WebSocket declarations could not resolve `@types/ws`, and an x402 declaration
could not resolve Node's `Buffer` type.

`@types/node` and `@types/ws` now ship as regular package dependencies at their
existing version ranges. Consumers receive them transitively instead of having
to discover and install missing ambient types themselves. The production lock
also includes the required `undici-types` dependency. This follows the
[TypeScript declaration publishing guidance](https://www.typescriptlang.org/docs/handbook/declaration-files/publishing.html#dependencies).

## Install

After the tagged v0.8.2 archive is published:

```sh
npm install https://github.com/InTheta/omni-universe-sdks/releases/download/v0.8.2/omni-terminal-sdk-0.8.2.tgz
```

Until then, build the reviewed source revision using `npm ci && npm run verify`
from `packages/typescript`. Node >=22.12 remains required. No additional ambient
type installation or `skipLibCheck` workaround is needed. A merge does not prove
that the release asset has been published; npm registry publication remains a
separate step.

v0.8.1 is not replaced or retagged. Existing consumers can upgrade to v0.8.2
without changing their public SDK imports. See the preserved
[v0.8.1 notes](0.8.1.md) for the feature and runtime migration introduced there.

## Permanent package verification

`npm run test:package`, included in `npm run verify`, now:

1. Packs the built SDK and installs only that tarball into a fresh consumer
   directory with install scripts disabled.
2. Compiles root and broker imports, WebSocket options, PNG helpers, recent
   reconciliation types and a negative internal-export check.
3. Uses strict `NodeNext`/`ES2022`, `noEmit: true` and
   `skipLibCheck: false`. It does not install consumer dev dependencies or
   ambient-type workarounds.
4. Performs the existing JavaScript import and package-version smoke checks.

The repository's compiler is the test tool; declarations and ambient types
resolve from the isolated consumer's SDK dependency tree. The strengthened
check reproduced the v0.8.1 failure before the dependency fix.

This release changes package/type availability and version metadata, not
trading authority, paid-request budgets or execution policy. Previously stated
funded lifecycle, complete-ledger and authoritative builder-attribution gaps
remain unverified.
