# v0.8.4: payment verification error-code diagnostics

This patch preserves allowlisted verification reasons supplied in the x402 v2
`PAYMENT-REQUIRED` header's `error` field when an HTTP 402 response has no
recognized body error code. An existing recognized body code takes precedence.
`OmniApiError.code` can now identify canonical reasons such as
`invalid_exact_evm_signature`, `invalid_exact_evm_nonce_already_used` and
`invalid_exact_evm_insufficient_balance` without exposing the decoded challenge,
payment proof or seller response body.

Header parsing is limited to HTTP 402 and bounded to 16 KiB before decoding.
Malformed, oversized, unsupported-version and unrecognized header errors retain
`HTTP_ERROR`. Existing allowlisted legacy/custom body codes remain supported.
This changes diagnostic mapping only: there is no retry, signing, settlement,
authorization-hold or paid-response recovery change. An error code does not prove
whether a payment settled or authorize another payment. Preserve reconciliation
requirements and obtain authoritative evidence before a newly authorized attempt.

## Install

Once the immutable tagged archive is published:

```sh
npm install https://github.com/InTheta/omni-universe-sdks/releases/download/v0.8.4/omni-terminal-sdk-0.8.4.tgz
```

Node >=22.12 remains required. See [installed quickstarts](../installed-quickstarts.md)
for SDK-only commands and the separate source installation required for the local
MCP trading adapter. Earlier release tags/assets remain unchanged; this document
does not claim npm registry publication or that the v0.8.4 asset is already live.

## Verification boundary

The regression tests use injected HTTP response fixtures to exercise recognized
header codes, body-code precedence, malformed/oversized headers, version/status
checks and redaction. They make no payment, venue order or paid provider call.
They test local SDK error handling, not a fresh facilitator rejection, on-chain
proof replay or expiry, settlement, funded trading lifecycle, or builder credit.
Release-gate and installed-package results must be reported separately from these
offline fixtures.
